# Two Very Different Bikes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Add a Dirt Jumper and an Enduro to the feel lab: each a set of ride-setting overrides plus its own frame
look, swappable in place mid-ride.

**Architecture:** A new lab-only module (`src/lab/bikes.ts`) holds the four lab bikes, each bike's overrides on
the Tune settings, and `applyBike`, which writes them into the live `T`. The rider model splits bike geometry from
rider size: each bike may carry a frame shape and a rider scale; Bolinas and Bayview keep today's look. `createRide`
gains `setBike`, which rebuilds the rig in place; the lab page adds the two bikes to the picker and a Swap bike
button.

**Tech Stack:** TypeScript 5.6, three.js 0.170, Vite 5.4, Vitest 2.1. Headless checks use Playwright's cached
Chromium over CDP (see `checks/climb-shots.mjs` for the pattern).

**Spec:** `docs/superpowers/specs/2026-11-01-two-bikes-design.md`

## Global Constraints

- Feel lab only (`/lab.html`). No changes to `/play.html`, `src/game/`, the save game, or the `BikeId` type the game
  uses.
- No parts, bolts, prices or unlocks. No bike-only behaviors (that's iteration B).
- Bolinas and Bayview look and ride exactly as today.
- The rider is the same size on the Dirt Jumper and the Enduro.
- Dirt Jumper wheels ~24" (radius 0.29 m); Enduro 29" (radius 0.38 m).
- Not a git repo: there are no commit steps. `npm run check` and `npm test` must pass at the end of every task.
- Dev server at `http://127.0.0.1:5173` (not `localhost`).

## Review Focus

1. Swapping from the Dirt Jumper back to Bolinas must not leave dirt jumper numbers in `T` (Task 1 test).
2. Saved Tune values from an earlier session must not beat the chosen bike's numbers at start (Task 3 check).
3. Swapping mid-crash (rider tumbling) must not leave the old bike or rider in the scene (Task 3 check).
4. The Swap button's tap must not reach the stick or Jump (Task 3 check).
5. New frames must sit on the ground: wheels touching, not floating or sunk (Task 2 test).

**Interfaces:**
- Produces, in `src/lab/bikes.ts`:
  - `type LabBikeId = BikeId | 'dirtjumper' | 'enduro'`
  - `LAB_BIKES: Record<LabBikeId, BikeSpec>`: `bolinas` and `bayview` are the existing `BIKES` entries, unchanged.
  - `LAB_ORDER: LabBikeId[] = ['dirtjumper', 'enduro', 'bolinas', 'bayview']` (picker order and swap order)
  - `BIKE_RIDE: Record<LabBikeId, Partial<Record<TuneKey, number>>>` (`{}` for bolinas and bayview)
  - `RIDE_KEYS: TuneKey[]`: every key any bike overrides
  - `applyBike(id: LabBikeId, t: Record<TuneKey, number> = T): void`: for each of `RIDE_KEYS`, sets
    `t[k] = BIKE_RIDE[id][k] ?? DEFAULTS[k]`; leaves every other key alone
  - `nextBike(id: LabBikeId): LabBikeId`: the next in `LAB_ORDER`, wrapping
- Produces, in `src/rules/bikes.ts`:
  ```ts
  export interface FrameShape { // model units: the rig is modeled for a 0.36 wheel, then scaled by riderScale
    axle: number;              // half the wheelbase (today 0.58)
    bb: [number, number];      // bottom bracket x, y (today -0.04, 0.33)
    seat: [number, number];    // (today -0.27, 0.9)
    htTop: [number, number];   // head tube top (today 0.36, 0.92)
    htBottom: [number, number];// head tube bottom (today 0.44, 0.72)
    bar: [number, number];     // stem top, where the hands go (today 0.42, 1.04)
    barHalf: number;           // half the bar width (today 0.34)
    fork: 'plain' | 'travel';  // 'travel' draws fat stanchions
    shock: boolean;            // draws a rear shock
  }
  ```

### Task 2: Each bike looks like its type

**Files:**
- Modify: `src/bike/rider.ts`
- Modify: `src/lab/bikes.ts` (fill in `frame` for `dirtjumper` and `enduro`)
- Test: `tests/rider.test.ts`

**Interfaces:**
- Consumes: `FrameShape`, `BikeSpec.riderScale`, `BikeSpec.frame` (Task 1); `LAB_BIKES`, `LAB_ORDER` (Task 1)
- Produces, in `src/bike/rider.ts`:
  - `DEFAULT_FRAME: FrameShape`: today's constants (`axle 0.58, bb [-0.04, 0.33], seat [-0.27, 0.9], htTop
    [0.36, 0.92], htBottom [0.44, 0.72], bar [0.42, 1.04], barHalf 0.34, fork 'plain', shock false`)
  - `riderScaleOf(spec: BikeSpec): number`: `spec.riderScale ?? spec.wheelRadius / RIG_WHEEL`
  - `frameOf(spec: BikeSpec): FrameShape & { wheel: number }`: `DEFAULT_FRAME` overlaid with `spec.frame`, plus
    `wheel = spec.wheelRadius / riderScaleOf(spec)` (model-unit wheel radius)
  - `createRider(spec)` keeps its signature.

**How the model changes:**
- `root.scale` is `riderScaleOf(spec)` (unchanged for Bolinas and Bayview).
- Wheels sit at `±axle`, centered at `y = wheel`, torus radius `wheel`; `manualG.position.x = -axle` and
  `body.position.x = axle`. The frame tubes, chainstays, seatstays and fork use the frame's points; the rear
  triangle meets the rear axle at `(-axle, wheel)`, the fork the front axle at `(axle, wheel)`.
- `'travel'` fork: thicker stanchions (radius ~0.05) and a brace. `shock: true`: a short fat cylinder from the
  seat tube's middle to the top tube's middle, in a contrasting color.
- The rider follows the bars: offset the rider's hip, shoulder, head and arms by `bar - DEFAULT_FRAME.bar`, and
  solve the legs from the offset hip to pedals turning round `bb`. A dirt jumper rider stands taller over a low
  bike; that's correct for the type.
- Starting frames (tune by eye from the screenshots in Task 3):
  - `dirtjumper`: `axle 0.5, bb [-0.04, 0.3], seat [-0.24, 0.62], htTop [0.33, 0.8], htBottom [0.4, 0.62],
    bar [0.39, 0.92]`, `fork 'plain'`, no shock.
  - `enduro`: `axle 0.68, bb [-0.04, 0.36], seat [-0.3, 0.95], htTop [0.42, 0.98], htBottom [0.52, 0.74],
    bar [0.47, 1.08], barHalf 0.38`, `fork 'travel'`, `shock true`.

### Task 3: Swap bikes in the lab

**Files:**
- Modify: `src/lab/ride.ts` (`setBike`, a shared `clearTumble`, `rig` becomes `let`)
- Modify: `src/lab/main.ts` (picker from `LAB_BIKES`, `applyBike` at start, Swap button, `B` key, `__lab` additions)
- Modify: `src/lab/tune.ts` (`createPanel` returns `refresh`; takes an `onReset` hook)
- Modify: `lab.html` (four picker buttons in `LAB_ORDER` order, with each bike's color)
- Modify: `src/lab/lab.css` (Swap button: top left, clear of the stick)
- Create: `checks/bike-swap.mjs`

**Interfaces:**
- Consumes: `LAB_BIKES`, `LAB_ORDER`, `applyBike`, `nextBike`, `LabBikeId` (Task 1); `createRider` (Task 2)
- Produces:
  - `Ride.setBike(spec: BikeSpec): void`: clears any tumble (the same `clearTumble()` that `teleport` now uses),
    removes the old `rig.root` from the scene and disposes its geometries (not its materials: `mat()` may share
    them), builds and adds a new rig, and `Object.assign(s.bike, spec)`. Position, yaw and speed are untouched.
  - `createPanel(...)` returns `{ toggle(): void; refresh(): void }`; its `on` argument gains `reset(): void`,
    called after Reset restores the defaults, so the current bike's ride is reapplied.
  - `window.__lab` gains `bike: () => LabBikeId` and `swap: () => void` for checks.

**Behavior:**
- Start: `loadTune()`, then `applyBike(id)`, then `createRide`. A saved Tune value for a bike-owned key never beats
  the chosen bike.
- Swap button label: `🚲 <next bike's name>`. Tap: `id = nextBike(id)`, `applyBike(id)`, `ride.setBike(...)`,
  `panel.refresh()`, update the label. The button is a real `<button>` outside the canvas, so its touch never
  reaches the pad.
- Tune Reset: defaults, then `applyBike(current)`, then refresh.
