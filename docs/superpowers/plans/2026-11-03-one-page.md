# One Page (Game + Feel Lab) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make `/play.html` the one page: profiles, challenges without stars, three bikes (Dirt Jumper, Enduro,
Bolinas; the Bayview is dropped) with their own tricks, Tune and Swap. `/lab.html` redirects to it.

**Architecture:** Build on the game page (`src/game/main.ts`). Strip the garage, bolts, stars and lessons; bring in
the lab's bikes (`src/lab/bikes.ts`), Tune panel (`createPanel`) and Swap button. Bike tricks are one data table
(`src/game/bikeTricks.ts`) feeding the existing swipe gate (`src/game/unlocks.ts`). The save keeps every old field
untouched.

**Tech Stack:** TypeScript 5.6, three.js 0.170, Vite 5.4, Vitest 2.1. Headless checks: Playwright's cached Chromium
over CDP (pattern in `checks/bike-swap.mjs`).

**Spec:** `docs/superpowers/specs/2026-11-03-one-page-design.md` (read it first). The tricks table there is
confirmed by the user.

**Read first:** `docs/handoff-2026-11-01.md` (the project, how to run things, the two-bikes piece).

## Global Constraints

- Dev server at `http://127.0.0.1:5173` (not `localhost`); `npm run dev` if it isn't running.
- Not a git repo (unless the user has run `git init`): no commit steps. If there's no git, snapshot `src tests
  checks lab.html play.html docs` into the scratchpad before Task 1, for the final review's diff.
- `npm run check` and `npm test` must pass at the end of every task.
- Never drop fields from the save (`shredder-save`): bolts, parts, learned and stars must load and save back
  unchanged.
- Bike names and order come from `LAB_BIKES` / `LAB_ORDER` in `src/lab/bikes.ts`; don't retype them.
- The Bayview leaves the lab bikes only. `BIKES` in `src/rules/bikes.ts` keeps it (the old `/` prototype and
  existing tests use it).
- No changes to the old `/` prototype (`index.html`, `src/game.ts`, `src/main.ts`).
- Keep `src/game/parts.ts`, `progress.ts`'s star and bolt functions, and `challenges.ts`'s star scoring: unused for
  now, back later. Their tests stay.

## Review Focus

1. An old save with bolts, parts, stars and learned tricks: everything survives load → swap → save (Task 2 test).
2. Swap while a challenge card, sheet, countdown or Tune is open: the button is hidden (Task 3 check).
3. The hints round Jump never offer a trick the bike can't do, including right after a swap (Task 1 test, Task 3
   check).
4. `?bike=` with an unknown id: "Who's riding?" shows as normal, no error (Task 3 check).
5. A swap mid-challenge: the challenge carries on, on the new bike, and the hints change (Task 3 check).
